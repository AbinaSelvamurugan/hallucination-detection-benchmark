# Model implementation and limitations

1. **Lexical overlap:** `|informative_answer_tokens ∩ informative_evidence_tokens| / |informative_answer_tokens|`; a high score may simply reflect copied entities, dates or negations. No calibrated probability. Zero-content answers -> abstain. Hard threshold may be chosen on validation only.
2. **Semantic similarity:** documented cosine similarity between normalized MiniLM sentence vectors; model `sentence-transformers/all-MiniLM-L6-v2` pinned to `c21050a7ef692090620a6d037dd736908f9c7cf6`. High similarity can tolerate flipped negations, swapped people and numerals. Single long evidence may be truncated by the encoder. Threshold on validation only.
3. **NLI:** `cross-encoder/nli-deberta-v3-base`, pinned `051133896da0ee0fa7074a5e36bde50b5d9443da`. The model's `config.id2label` is checked at load, not assumed; card indicates contradiction=0, entailment=1, neutral=2. Premise=evidence and hypothesis=answer; model inference with softmax is **not calibrated**. Entailment -> supported; contradiction -> contradicted; neutral -> unsupported. Long pairs truncate premise to 512 tokens; this can cause apparent unsupportedness even if evidence exists beyond input window. Textual inference is not absolute fact verification.
4. **LLM judge:** Optional `openai` client with explicit provider/model. Prompt includes question, evidence and full response, structured JSON schema-like rubric, flagged claims, verbatim evidence excerpts, brief reasoning, abstention. Strict post-response checking rejects missing keys, invalid labels and invented evidence excerpts. Parsing/runtime/API failure -> `error`, never a label. Logs response model, limited usage metadata and rubric; model version must be specified explicitly. No self-confidence calibration claims. Users must comply with provider handling and privacy terms; API costs depend on pricing/usage and are not invented.
5. **TF-IDF logistic regression:** `TfidfVectorizer(1,2)` + `LogisticRegression(random_state=17)` fit on **train** only; threshold fitted on **validation** positive F1, serialized to trusted joblib checkpoint. Outputs probability-like discriminative scores that can be evaluated for calibration, not presumed calibrated. Input includes prompt/evidence/answer and should be scrutinized for dataset-specific templates. No model checkpoint ships. **Never load untrusted joblib files**.

## Shared interface

`Prediction` carries `example_id`, detector/version, `label`, `scores`, `probability_kind`, `status`, error text, latency, evidence references and metadata. Status `ok` alone enters classification counts; `abstained`, `missing_evidence`, `error`, `unavailable` remain observable exclusions. Device selection, local-only model loading and lazy reuse are configured per detector. `close()` frees in-process model references. Optional packages are imported on demand.

**Cost:** Local inference runtime/CPU/GPU RAM depend on hardware; the run captures wall time and per-prediction latency but not peak RAM or energy. Provider billing not inferred. Model downloads/caching require network and storage; a typical remote judge additionally incurs per-request fees and latency. Report exact purchased token rates only if provider supplies them and your experiment records pricing date.
